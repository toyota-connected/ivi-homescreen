# Plugins

## Static plugins
Static plugins are linked directly into the `ivi-homescreen` binary at build time, and are registered with the Flutter engine through the standard static plugin registration mechanism.

To include a static plugin in your `ivi-homescreen` build, when building the binary pass a semicolon-separated list of plugin source directories to the `STATIC_PLUGIN_DIRS` when building the `homescreen` binary, and the build system will take care of building and linking the plugins into the binary.

The plugins however will be only initialized at runtime if the given app calls for them (i.e. if they are included in the `pubspec.yaml` dependencies and thus in the generated `.plugins` file), otherwise they will be left uninitialized and won't consume any runtime resources.

## Dynamic plugin loading
Differently from the vanilla Flutter (Linux) embedder, `ivi-homescreen` additionally provides an ABI for plugins to be loaded as dynamic libraries at runtime.

This enables the following use cases:
- **Verifiable binaries**: Both `ivi-homescreen` and the plugins can be built and signed independently inside of trusted build pipelines with full transparency and audit trail.
- **Dynamic updates**: Plugins can be updated independently of the embedder, allowing for faster iteration and deployment of plugin updates without needing to rebuild the entire embedder**.
- **Third-party plugins**: this paves the road for third-party developers to create and distribute their own plugins without having to depend on the `ivi-homescreen` ecosystem - this is achieved via an ABI wrapper that is used to link existing plugins to the `ivi-homescreen` plugin ABI.
- **Reduced attack surface**: by only loading plugins that are needed for a specific use case, the attack surface of the embedder can be reduced, improving security.

## Usage Guide

**Start here**: When creating a plugin, start from the [`ivi-homescreen-plugin-template`](https://github.com/toyota-connected/ivi-homescreen-plugin-template) repository; it provides a complete example of a plugin including the necessary build files.

### 1. Building Plugins

**Follow [README](https://github.com/toyota-connected/ivi-homescreen-plugin-template/tree/main/README.md) instructions in the `ivi-homescreen-plugin-template` repository** to build your plugin, which will output a dynamic library (`.so` file) that can be loaded by `ivi-homescreen`.


### 2. Distributing & Loading Plugins

By default the `homescreen` binary looks for plugins in the `lib/plugins` path relative to the given bundle directory, and searched recursively for any dynamic libraries that match the plugin ABI. Each plugin is expected to be in its own subdirectory under `lib/plugins`, and the plugin dynamic library must be named `lib<plugin_name>.so`.

> **For `meta-flutter/workspace-automation` users**: this is configured to link the `app/ivi-homescreen/build/plugins` directory to `lib/plugins` in the bundle directory. Your plugins should be configured to output their dynamic libraries to `app/ivi-homescreen/build/plugins/**/lib<plugin_name>.so`.

##### Signature Verification

`ivi-homescreen` will verify the signature of each plugin before loading it.

A missing or invalid signature will result in the plugin being rejected and not loaded, and an error message will be logged - **unless** `ivi-homescreen` is either:
- Running in debug mode (will still display a warning)
- Built with the `ALLOW_UNSIGNED_PLUGINS` flag enabled
